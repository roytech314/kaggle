# 評価結果と改善方針

目標: Kaggle Public RMSLE 0.40未満。RMSLEは小さいほど良い。

## 確認済みの結果

| 比較 | 曜日平均 | LightGBM | ランダムフォレスト |
|---|---:|---:|---:|
| 初回の単一16日検証 | 0.53113 | 0.41968 | — |
| 2016〜2017年の4期間平均 | 0.55731 | 0.50221 | 0.52872 |
| Kaggle Public（ユーザー報告） | **0.44491** | 0.52606 | 未提出 |

初回の検証と複数期間比較では、学習初期56日の扱い等が異なるため同じ条件ではない。複数期間比較ではLightGBMとRFの入力情報・学習行・目的変数を揃えているが、カテゴリ/欠損の処理やモデル設定はそれぞれ異なる。パラメーター探索は未実施。

- LightGBMは固定した近年4区間で曜日平均を改善した。RFは3区間で改善したが、年末区間で悪化した。
- 近年4区間ではLightGBMの学習を直近365日に絞っても、平均スコアはほぼ変わらなかった。
- KaggleではLightGBMが曜日平均より0.08115（約18.2%）悪化した。現在の最良提出は曜日平均。過去検証の改善だけで提出モデルを優れているとは判断できない。
- 古い4区間には大きな変動があり、特に2014年8月は曜日平均の誤差が大きい。古い期間だけの良いスコアを採用しない。

根拠: [モデル比較](model-comparison.md)、[年代別比較](backtest-results.md)、`experiments/` の評価JSONと `submissions.csv`。PublicスコアはKaggle APIによる取得ではなくユーザー報告として記録している。

## データから確認した特徴

- 54店舗×33カテゴリの1,782系列。販売数量を16日先まで予測する。
- ゼロ売上の行は31.30%。カテゴリによってゼロ率・数量規模が大きく異なる。
- 年をまたぐ規模の増加と12月の上振れがあり、年内に単調増加しているわけではない。
- 2013〜2016年の12月25日は行がない。欠測行を売上0として扱わない。
- 取引件数と売上に相関があるが、テスト期間の取引件数は提供されていない。

根拠: [データ概要](data-overview.md)、`survey.py` による元CSVの集計。

## 現在のLightGBM

全店舗・カテゴリを一つのモデルで学習する。入力は店舗・カテゴリ・販促数、日時5個、売上ラグ5個、移動平均2個の計15特徴量。目的変数はlog1p売上で、学習率0.05・300回・葉数31・葉の最小件数100。

ラグは16・21・28・35・56日前、移動平均は16日前を末尾とする7日・28日平均。一律16日シフトは未来実績の混入を防ぐが、予測起点直前の情報を十分に利用できていない。例えば8月16日の予測に対し、売上由来の最新特徴量は7月31日までを参照する。

## 次の改善候補（未実装・未評価）

1. **検証と提出の処理を統一する。** 学習開始日・準備期間・ラグ用履歴の扱いを設定として共通化する。
2. **予測起点基準の特徴量を試す。** 起点直前の売上・平均・ゼロ率と予測日までの日数を使う。学習時も過去の起点を再現し、未来の実売上を混ぜない。
3. **店舗・カテゴリ・予測先日数別の誤差を調べる。** 曜日平均に負ける系列や期間を特定する。
4. **祝日・販促変化等を一種類ずつ比較する。** 地域と振替を考慮し、予測時点で入手できる情報に限定する。
5. **LightGBMの設定と特徴量の削減を比較する。** 葉数・最小葉件数・正則化・学習率/回数などを、共通の時系列検証で評価する。

2016〜2017年の固定4区間を主な比較セット、2013〜2014年を補助セットにする。既に繰り返し参照している検証期間への過度な適合にも注意し、最終判断には未使用期間の確認を残す。候補の効果と0.40未満の達成は未確認。
