# 年代・季節別の検証結果

実験記録: `experiments/backtests/20261031T024927Z.json`。指標はRMSLE（小さいほど良い）。評価期間はスコアを見る前に選んだ8つの16暦日区間。クリスマスの行がない年末区間は観測15日を採点する。

学習方式の起点は2013-01-01または2016-01-01。2015年は除外。LightGBMの初期56日は特徴量の準備期間として学習対象から外す。直近365日方式は利用できる履歴が1年未満の場合、年代内の履歴方式と同じデータになる。両方式が同条件の区間は独立した証拠として数えない。曜日平均は各起点の直近28日を使う。

## 年代ごとの判断

- 2013〜2014年: 曜日平均の平均RMSLEは0.83353、LightGBMは履歴方式0.57059、直近365日0.52464。平均には2014年8月の大きな誤差が強く影響する。LightGBMは4区間中3区間で良い。
- 2016〜2017年: 曜日平均0.55731、履歴方式0.50221、直近365日0.50259。LightGBMは4区間とも良いが、学習を直近365日に限定する効果はほとんど見えない。

平均は各区間のRMSLEの単純平均であり、全行をまとめたRMSLEではない。2017-07-31の値は初期56日の扱いが異なるため、以前の単一期間評価0.41968とは直接同条件ではない。

## 年内傾向

[年内パターン図](../result/backtest_seasonality_20261031T024927Z.png)は、月の日次平均を絶対値と各年の観測月平均で正規化した値で比較する。2017年は8月15日までで、年末の評価はできない。

2013・2014・2016年には12月の上振れがある。一方、2014年は春〜夏にも大きな上下があり、2016年には4月の山もある。2017年の1〜8月は比較的横ばい。「年初から年末へ毎月一様に増える」とは言えない。全体の長期増加と季節的な上振れを区別して扱う必要がある。正規化しても年内のトレンドや販促等を除去したことにはならない。

## 推奨する検証方針

本番に近い2016〜2017年の4区間を主な比較セットとして固定し、2013〜2014年は構造変化に対する補助的な確認に使う。年末区間は季節変動への耐性、夏の区間は提出対象に近い時期を確認する。スコアの良い区間だけを採用しない。

これらの過去検証ではLightGBMが良くても、Kaggleでは曜日平均0.44491、LightGBM0.52606と逆転した。検証期間の選び方だけが原因だったとは結論できない。次の確認候補は、前年の8月16〜31日を含む未使用期間、店舗・カテゴリ別の予測誤差、テスト期間と学習期間の入力分布の違い。今回結果を見た後の追加比較は探索的な検証として区別する。
